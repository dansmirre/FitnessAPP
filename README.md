# FORMA 2.0 · FitnessAPP

Фитнес Mini App для Telegram и браузера. Главная с аватаром, редактируемые упражнения с медиа, профиль, журнал тренировок и XP. Версия 2.0 добавляет синхронизацию устройств и объединение офлайн-записей.

## Запуск

Node.js 20+ (проверено на 24), npm-зависимостей нет.

```bash
npm start
npm test
```

Откройте http://localhost:3000. Для другого порта: `PORT=8080 npm start`.

## Офлайн

Откройте приложение один раз с интернетом на HTTPS (или localhost при разработке), чтобы Service Worker сохранил интерфейс. После этого профиль, упражнения, активная тренировка и история доступны без сети. При желании установите приложение на домашний экран из меню браузера. Очистка данных браузера удаляет локальные записи и ключ подключения; экспортируйте резервные копии в «Профиле».

Изменения сохраняются на устройстве и отправляются при возвращении сети, открытии приложения, нажатии «Синхронизировать сейчас» и каждые 30 секунд, пока приложение открыто. Закрытое приложение синхронизируется при следующем открытии. Внешние фото/видео и Telegram SDK не кэшируются. Поддержка Service Worker в Telegram зависит от клиента: отдельный браузер надёжнее для офлайн.

## Синхронизация устройств

1. Запустите эту версию на **одном общем HTTPS-сервере** с постоянным диском.
2. На первом устройстве откройте «Профиль → Синхронизация → Создать ключ синхронизации».
3. Нажмите «Показать ключ подключения» и сохраните ключ в надёжном месте.
4. На втором устройстве откройте тот же HTTPS-адрес, введите ключ в профиле и нажмите «Подключить устройство».
5. Дождитесь статуса «Синхронизировано». Теперь можно работать без сети; записи объединятся при следующем подключении.

Ключ — случайный секрет из 256 бит. Он даёт полный доступ к данным, поэтому передавайте его только своим устройствам. Ключ не передаётся в URL и не хранится на сервере в открытом виде: имя файла определяется его SHA-256 хэшем. На клиенте ключ хранится в localStorage. Синхронизация не является сквозным шифрованием: администратор сервера может читать данные. Восстановления потерянного ключа и автоматического входа через Telegram пока нет. Отключение устройства удаляет ключ только с этого устройства; копии ключа остаются действительными. Утечка ключа требует нового ключа и переноса записей через JSON; старые данные удаляет администратор сервера.

Тренировки объединяются по уникальному ID, XP считается из истории без повторного начисления. Профиль и упражнения объединяются по полям/записям: при конкурирующем изменении выигрывает более поздняя отметка устройства (при равенстве — ID устройства). Часы устройств должны быть корректны. Удаление упражнения сохраняется как отметка удаления. Активная незавершённая тренировка остаётся локальной. При первом подключении профиль и совпадающие упражнения из облака имеют приоритет, локальная история и новые упражнения объединяются. Для нескольких людей создавайте отдельные ключи.

## Развёртывание сервера

```bash
PORT=3000 FORMA_DATA_DIR=/var/lib/forma node server.js
```

`FORMA_DATA_DIR` должен указывать на **постоянный защищённый диск** с правами записи для процесса Node. По умолчанию `.forma-data/` в каталоге проекта (исключён из Git). Сохраняйте резервные копии этого каталога. Один процесс Node обслуживает файловое хранилище; несколько реплик/процессов с одним диском не поддерживаются. Записи сохраняются атомарным переименованием и переживают перезапуск. Лимит документа аккаунта — 2 МБ / 10 000 записей, медиа хранятся как внешние ссылки.

Для доступа с других устройств поставьте сервер за HTTPS reverse proxy, проксируйте `/api/sync` вместе с файлами и сохраняйте исходный Host. Добавьте на прокси ограничения частоты запросов и общего дискового пространства перед публичным запуском. При работе за прокси не публикуйте Node-порт напрямую в интернет. В приложении нет CORS-разрешений для чужих сайтов. При потере/недоступности серверного диска синхронизация сообщает ошибку, локальные данные остаются доступны.

GitHub Pages поддерживает только статическую офлайн-версию, **API синхронизации там не работает**. Загрузка кода в GitHub не развёртывает сервер. HTTPS-хостинг и постоянный диск нужно настроить отдельно. В Telegram задайте адрес вашего сервера в Mini App / кнопке меню через BotFather. Токен бота клиенту не нужен. Telegram initData пока не используется для входа.

## Проверка

`npm test` проверяет завершение тренировок и XP, объединение двух устройств после офлайна, удаления, конфликты полей, валидацию, изоляцию ключей, конкурентные запросы и сохранность после перезапуска сервера.

Для ручной проверки откройте два браузера с одним ключом, отключите сеть в одном, завершите разные тренировки в обоих, восстановите сеть и синхронизируйте. Обе тренировки и суммарные XP должны появиться на обоих устройствах.

Аватар — условная иллюстрация с ручной настройкой ширины, не измерение реальных изменений тела.
