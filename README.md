# FORMA 2.3.0 · FitnessAPP

Фитнес Mini App для Telegram и браузера. Главная с аватаром, редактируемые упражнения с медиа, профиль, журнал тренировок и XP. Версия 2.0 добавляет синхронизацию устройств и объединение офлайн-записей.

Версия 2.0.1 исправляет создание упражнений, тренировок и запуск синхронизации на HTTP-адресах NAS: генерация идентификаторов больше не требует `crypto.randomUUID`. Для доступа из интернета и передачи ключей используйте HTTPS; офлайн-кэш также требует HTTPS или localhost.

## Новое в 2.3

Новый профиль: вращающийся базовый мужской/женский 3D-персонаж, пять этапов телосложения, уровень, XP и число тренировок, расписание, журнал веса, параметры, синхронизация, экспорт/импорт и локальный сброс. При недоступности WebGL остаётся 2D-иллюстрация. Инструкция по созданию детальных моделей и подключению своих `male.glb`/`female.glb`: [AVATARS_3D.md](AVATARS_3D.md).

Журнал веса: одно взвешивание на дату, добавление/исправление/удаление, периоды 30/90 дней и всё время, график по реальным датам. Текущий вес определяется последней записью; изменение старой даты не заменяет более новое измерение. При миграции старого профиля сохраняется стартовое измерение с датой обновления приложения — исторические даты не выдумываются. Записи объединяются между устройствами по отдельным ID, удаление сохраняет отметку удаления.

Расписание начинает учитывать пропуски после «Закрепить дни», с даты закрепления, по календарю устройства. Сегодня не считается пропущенным. Тренировка в любой день прерывает текущую цепочку пропусков. После одного/двух пропусков появляются напоминание/предупреждение в интерфейсе. Каждый третий пропуск подряд удерживает игровой XP двух последних предшествующих тренировок; один и тот же XP дважды не удерживается. История и начисленный XP остаются исходными, уровень/главная/профиль используют XP после удержаний. При смене расписания уже рассчитанные удержания сохраняются. Push-уведомлений нет. Часы и часовой пояс устройств должны быть корректны.

Этапы телосложения: от стартового образа добавляется по этапу на уровнях 6, 11, 16, 21, максимум пять. Это игровая прогрессия, не измерение физических изменений. Изменить стартовый образ и параметры можно через «Изменить».

«Сбросить всё» требует подтверждения и очищает только записи и ключ синхронизации FORMA на этом устройстве. Серверные данные и другие устройства не удаляются. Повторное подключение старым ключом вернёт серверную копию.

При обновлении до 2.3 обновите сервер и все устройства: старый сервер не распознаёт новые записи журнала веса. Запуск готовой версии не требует загрузки зависимостей; для пересборки 3D-кода выполнить `npm ci && npm run build:avatar`. В поставке используются Three.js (MIT) и сборка esbuild; лицензия Three.js включена в репозиторий.

## Новое в 2.2

Раздел «Прогресс»: последние 7/30 календарных дней (с начала первого дня до текущего момента, по часовому поясу устройства) или вся история, число тренировок, объём в тоннах, текущий вес из профиля. График объёма по неделям с понедельника: неполные недели учитывают только записи выбранного периода, для всей истории показаны последние 12 недель. Нажатие на столбец раскрывает точный объём.

Нагрузка по группам считается из сохранённых в тренировках упражнений; для старых записей без группы используется текущий каталог либо «Без группы». Динамика упражнения сравнивает максимальный рабочий вес первой и последней тренировки за период по ID упражнения; требует минимум двух тренировок. Объём — подходы × повторения × внешний вес: без отягощения он нулевой. Изменение рабочего веса не равно изменению силы и не учитывает качество техники.

На странице отображаются три последние тренировки выбранного периода, «Весь журнал» открывает всю историю с подробностями. Разбор прогресса формирует локальные подсказки по правилам, работает офлайн, не отправляет запросов в ИИ. Внешний ИИ-тренер пока не подключён. Формат сохранений и синхронизации не изменён.

## Новое в 2.1

Первый запуск: выбор мужского/женского персонажа, имени, возраста, роста, веса, одного из пяти телосложений и уровня подготовки. Далее — информация о передаваемых данных и выбор синхронизации либо локального режима. При ошибке подключения можно повторить попытку или продолжить локально. Существующие профили и резервные копии сохраняют совместимость.

Главная: векторный персонаж с видами спереди/сзади (нажатие или горизонтальный жест), параметры, игровой показатель силы по числу тренировок, XP, выполненные подходы, уровень за каждые 70 XP, недельный счётчик и запуск/продолжение тренировки. Дни тренировок выбираются в профиле; подсказка отображается при открытии приложения, push-уведомлений нет. Достижения открываются за 1, 7, 30 и 100 тренировок. Пол, подготовка, телосложение и расписание синхронизируются вместе с профилем.

Персонаж — локальная 2D-иллюстрация, не 3D-модель и не измерение состава тела. Для реалистичного вращающегося персонажа нужны отдельные 3D-ресурсы. Внешние Supabase/Cloudflare и авторизация через Telegram не подключались. Самостоятельное удаление серверных данных и бонус XP за увеличение веса пока не реализованы.

## Запуск

Node.js 20+ (проверено на 24), Готовая браузерная сборка включена в репозиторий. npm-зависимости нужны для пересборки 3D-просмотрщика.

```bash
npm start
npm test
```

Откройте http://localhost:3000. Для другого порта: `PORT=8080 npm start`.

## Офлайн

Откройте приложение один раз с интернетом на HTTPS (или localhost при разработке), чтобы Service Worker сохранил интерфейс. После этого профиль, упражнения, активная тренировка и история доступны без сети. При желании установите приложение на домашний экран из меню браузера. Очистка данных браузера удаляет локальные записи и ключ подключения; экспортируйте резервные копии в «Профиле».

Изменения сохраняются на устройстве и отправляются при возвращении сети, открытии приложения, нажатии «Синхронизировать сейчас» и каждые 30 секунд, пока приложение открыто. Закрытое приложение синхронизируется при следующем открытии. Внешние фото/видео и Telegram SDK не кэшируются. Поддержка Service Worker в Telegram зависит от клиента: отдельный браузер надёжнее для офлайн.

## Синхронизация устройств

1. Запустите эту версию на **одном общем HTTPS-сервере** с постоянным диском.
2. На первом устройстве откройте «Профиль → Синхронизация → Создать ключ синхронизации».
3. Нажмите «Показать ключ подключения» и сохраните ключ в надёжном месте.
4. На втором устройстве откройте тот же HTTPS-адрес, введите ключ в профиле и нажмите «Подключить устройство».
5. Дождитесь статуса «Синхронизировано». Теперь можно работать без сети; записи объединятся при следующем подключении.

Ключ — случайный секрет из 256 бит. Он даёт полный доступ к данным, поэтому передавайте его только своим устройствам. Ключ не передаётся в URL и не хранится на сервере в открытом виде: имя файла определяется его SHA-256 хэшем. На клиенте ключ хранится в localStorage. Синхронизация не является сквозным шифрованием: администратор сервера может читать данные. Восстановления потерянного ключа и автоматического входа через Telegram пока нет. Отключение устройства удаляет ключ только с этого устройства; копии ключа остаются действительными. Утечка ключа требует нового ключа и переноса записей через JSON; старые данные удаляет администратор сервера.

Тренировки объединяются по уникальному ID, XP считается из истории без повторного начисления. Профиль и упражнения объединяются по полям/записям: при конкурирующем изменении выигрывает более поздняя отметка устройства (при равенстве — ID устройства). Часы устройств должны быть корректны. Удаление упражнения сохраняется как отметка удаления. Активная незавершённая тренировка остаётся локальной. При первом подключении профиль и совпадающие упражнения из облака имеют приоритет, локальная история и новые упражнения объединяются. Для нескольких людей создавайте отдельные ключи.

## Развёртывание сервера

```bash
PORT=3000 FORMA_DATA_DIR=/var/lib/forma node server.js
```

`FORMA_DATA_DIR` должен указывать на **постоянный защищённый диск** с правами записи для процесса Node. По умолчанию `.forma-data/` в каталоге проекта (исключён из Git). Сохраняйте резервные копии этого каталога. Один процесс Node обслуживает файловое хранилище; несколько реплик/процессов с одним диском не поддерживаются. Записи сохраняются атомарным переименованием и переживают перезапуск. Лимит документа аккаунта — 2 МБ / 10 000 записей, медиа хранятся как внешние ссылки.

Для доступа с других устройств поставьте сервер за HTTPS reverse proxy, проксируйте `/api/sync` вместе с файлами и сохраняйте исходный Host. Добавьте на прокси ограничения частоты запросов и общего дискового пространства перед публичным запуском. При работе за прокси не публикуйте Node-порт напрямую в интернет. В приложении нет CORS-разрешений для чужих сайтов. При потере/недоступности серверного диска синхронизация сообщает ошибку, локальные данные остаются доступны.

GitHub Pages поддерживает только статическую офлайн-версию, **API синхронизации там не работает**. Загрузка кода в GitHub не развёртывает сервер. HTTPS-хостинг и постоянный диск нужно настроить отдельно. В Telegram задайте адрес вашего сервера в Mini App / кнопке меню через BotFather. Токен бота клиенту не нужен. Telegram initData пока не используется для входа.

## Проверка

`npm test` проверяет завершение тренировок и XP, объединение двух устройств после офлайна, удаления, конфликты полей, валидацию, изоляцию ключей, конкурентные запросы и сохранность после перезапуска сервера.

Для ручной проверки откройте два браузера с одним ключом, отключите сеть в одном, завершите разные тренировки в обоих, восстановите сеть и синхронизируйте. Обе тренировки и суммарные XP должны появиться на обоих устройствах.

Аватар — условная иллюстрация с ручной настройкой ширины, не измерение реальных изменений тела.
